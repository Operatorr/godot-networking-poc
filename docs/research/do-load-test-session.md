## Hardware, billing, and routing

The operator's initial baseline is **two shared 2-vCPU/4-GiB Droplets in Singapore (`sgp1`)**. Basic Regular pricing is **$0.03571/hour per host**, $24 monthly cap, 80 GiB disk and 4,000 GiB monthly transfer. Pair compute is approximately $0.07142/hour; four hours is $0.28568 before extras/tax. Premium variants differ: the controller must query and persist the selected size slug, current price, and characteristics. Bundled Droplets bill per second, with minimum 60 seconds or $0.01; powered-off machines remain billable until destroyed. Dedicated CPU-Optimized 2-vCPU/4-GiB machines cost $0.06250/hour each and are a separate condition, not this baseline. [Pricing](https://www.digitalocean.com/pricing/droplets), [billing rules](https://docs.digitalocean.com/products/droplets/details/pricing/).

Basic plans are offered in `sgp1`; a public availability table does not prove account quota or live capacity. Authenticated `GET /v2/sizes` exposes slugs, prices, regions and availability. Query `GET /v2/regions`, account limits and image availability before purchase; treat create failures as possible even after preflight. No live account or stock claim is made here. [Regional availability](https://docs.digitalocean.com/platform/regional-availability/), [Sizes API](https://docs.digitalocean.com/reference/api/reference/sizes/).

Free transfer accrues with lifetime: `monthly allowance × seconds / 2,419,200`, pooled across the team. A 4,000 GiB host earns approximately 5.95 GiB/hour; two four-hour hosts earn approximately 47.62 GiB combined, not 8,000 GiB immediately. Public outbound overage is $0.01/GiB; inbound is free. Private VPC-interface traffic is distinct from public-interface traffic, which counts even between DO machines; IPv6 uses public networking. [Bandwidth rules](https://docs.digitalocean.com/platform/billing/bandwidth/).

Inference for comparison: shared CPU scheduling, architecture/CPU model, host co-location, region and public-versus-VPC routing all affect results. Record `lscpu`, steal time, kernel, clocks, routes, selected interfaces and hardware plan. The Droplet API exposes neighbor queries to detect same-hypervisor placement, not a placement guarantee. Equal vCPU/RAM labels cannot establish equivalence with CAX11. Routing choice remains a comparison-ticket decision. [Droplet API](https://docs.digitalocean.com/products/droplets/reference/api/droplets/), [plan characteristics](https://docs.digitalocean.com/products/droplets/concepts/choosing-a-plan/).

## API operations and least privileges

| Operation | API | Required operation scopes, plus listed dependencies |
| --- | --- | --- |
| Create, poll, destroy hosts | `POST /v2/droplets`; `GET/DELETE /v2/droplets/{id}` | `droplet:create`, `droplet:read`, `droplet:delete` |
| Inspect sizes and regions | `GET /v2/sizes`; `GET /v2/regions` | `sizes:read`, `regions:read` |
| Poll actions; select image/snapshot and VPC | relevant read APIs | `actions:read`, `image:read`, `snapshot:read`, `vpc:read` |
| Embed existing registered public key | creation `ssh_keys` | `ssh_key:read` |
| Create session tags during host creation; list/delete tags | `tags` field; `/v2/tags` | `tag:create`, `tag:read`, `tag:delete` |
| Create, inspect, refresh, delete session firewall | `/v2/firewalls` | `firewall:create`, `firewall:read`, `firewall:update`, `firewall:delete` |
| Assign hosts to existing project | `POST /v2/projects/{project_id}/resources` | `project:assign_resource`, `project:read` |

This is the union for that specific lifecycle, not every optional cloud feature. `droplet:create` explicitly requires the seven read scopes shown across the first three rows; embedding keys and tags adds their feature scopes. Firewall create/update requires firewall read; tag create requires tag read; project assignment requires project read. Account quota inspection adds `account:read`. Registering the public key once adds `ssh_key:create` (and read); it need not remain on the routine token. Post-creation resource tagging may need `droplet:update`; avoid it by tagging in creation. Creating snapshots is a Droplet action (`droplet:update`); deleting retained snapshots adds `snapshot:delete`. Image transfer and creation have their own feature scopes. No need for project deletion, key deletion, broad `api:write`, or console `droplet:admin` in the base runner. [Scope catalog](https://docs.digitalocean.com/reference/api/scopes/), [Droplet create dependencies](https://docs.digitalocean.com/reference/api/scopes/droplet/create/), [firewall create](https://docs.digitalocean.com/reference/api/scopes/firewall/create/), [firewall update](https://docs.digitalocean.com/reference/api/scopes/firewall/update/), [project assignment](https://docs.digitalocean.com/reference/api/scopes/project/assign_resource/), [tag create](https://docs.digitalocean.com/reference/api/scopes/tag/create/).

Creation accepts image ID, region, size, key IDs/fingerprints, tags, VPC UUID and cloud-init/user data (64 KiB maximum). Project assignment uses `do:droplet:<id>` URNs. Firewall rules can be updated via API when the operator changes IP, without needing SSH. Upload only the public key; the existing private Ed25519 key at `deployment/hetzner/ssh/omega_loadtest_ed25519` was confirmed Git-ignored and mode 0600 without reading it. Key authentication and source-IP filtering are complementary. No token/private key belongs in cloud-init, images, guest files or issue comments. [Droplets](https://docs.digitalocean.com/products/droplets/reference/api/droplets/), [projects](https://docs.digitalocean.com/reference/api/reference/project-resources/), [firewalls](https://docs.digitalocean.com/reference/api/reference/firewalls/), [SSH keys](https://docs.digitalocean.com/reference/api/reference/ssh-keys/), [repository access convention](https://github.com/Operatorr/godot-networking-poc/blob/0c9ecafa70adf4fbf2fee101f55a41b8c2ff19b6/deployment/hetzner/README.md).

## Bootstrap and reusable images

Existing cloud-init creates `deploy`, key-only access and build tools; it pins Rust **1.95.0** but pulls unversioned apt packages. Cargo.lock is tracked and `rusty_enet` is exactly pinned to `=0.4.0`; use `cargo build --release --locked` with the exact source SHA. An Ubuntu image slug or reusable snapshot does not alone pin compiler, dependencies, OS packages or actual binary identity: record numeric image/snapshot ID, toolchain, lockfile digest, package/kernel versions, clean source SHA and SHA256 of both native-architecture binaries. Build x86_64 for DO and ARM64 for CAX11 from the same source; binary hashes will differ across architectures. [Cloud-init](https://github.com/Operatorr/godot-networking-poc/blob/0c9ecafa70adf4fbf2fee101f55a41b8c2ff19b6/deployment/hetzner/cloud-init.yaml), [Cargo workspace](https://github.com/Operatorr/godot-networking-poc/blob/0c9ecafa70adf4fbf2fee101f55a41b8c2ff19b6/rust/Cargo.toml), [lockfile](https://github.com/Operatorr/godot-networking-poc/blob/0c9ecafa70adf4fbf2fee101f55a41b8c2ff19b6/rust/Cargo.lock).

Reusable snapshot IDs work as creation images where available; destination disk must be at least source disk size. Snapshots preserve disk content rather than IP/settings; they cost $0.06/GB/month after host deletion. Prefer a secret-free bootstrap snapshot with dynamic source/config deployment rather than freezing a moving game branch or IP allowlist. This is an implementation option, not a resolved image-policy decision. [Snapshot reuse](https://docs.digitalocean.com/products/snapshots/how-to/create-and-restore-droplets/), [snapshot costs](https://docs.digitalocean.com/products/snapshots/details/).

## Harness seams and recovery constraints

`quick_stress.sh` at the frozen head builds both executables, launches a LOCAL server, samples one host and targets `127.0.0.1`. It is not a remote two-host runner. It defaults threads to `min(4,nproc-1)`, which is one thread on a two-vCPU host: explicitly pass **two** for this rung. It records only short source SHA and one host; a remote adapter must supply full per-role provenance and both host streams. [Quick harness](https://github.com/Operatorr/godot-networking-poc/blob/0c9ecafa70adf4fbf2fee101f55a41b8c2ff19b6/scripts/quick_stress.sh).

The 1 Hz sampler emits cumulative process CPU/RSS, system steal, UDP counters, socket drops, wall time and a host-local monotonic clock. The report consumes `run.json`, bot report, server Tick CSV/server samples, one `host.ndjson` and logs, and derives a steady wall-time window from server start. Simply concatenating two hosts' streams is invalid: preserve separate streams and clock domains, server-socket versus bot-host counter identity, start/phase boundaries and generator headroom. Missing files degrade to n/a, so a remote controller must separately enforce evidence completeness and download checksums rather than accepting a rendered report as proof. [Sampler](https://github.com/Operatorr/godot-networking-poc/blob/0c9ecafa70adf4fbf2fee101f55a41b8c2ff19b6/scripts/quick_stress/sample_host.py), [report](https://github.com/Operatorr/godot-networking-poc/blob/0c9ecafa70adf4fbf2fee101f55a41b8c2ff19b6/scripts/quick_stress/report.py).

Existing `scripts/load_campaign/` already sequences runs on the same host pair, uses per-role collectors, records build provenance and downloads through a `.partial` file verified against remote SHA256 before rename. It hard-codes Hetzner access and old campaign/remote paths and is not a DO provisioner; reuse concepts instead of invoking its historical matrix. [Controller](https://github.com/Operatorr/godot-networking-poc/blob/0c9ecafa70adf4fbf2fee101f55a41b8c2ff19b6/scripts/load_campaign/run.py), [batch](https://github.com/Operatorr/godot-networking-poc/blob/0c9ecafa70adf4fbf2fee101f55a41b8c2ff19b6/scripts/load_campaign/campaign.py), [pinned build](https://github.com/Operatorr/godot-networking-poc/blob/0c9ecafa70adf4fbf2fee101f55a41b8c2ff19b6/scripts/load_campaign/build_hosts.py).

Inference from provider billing and API semantics: shell `trap`, guest poweroff, or a laptop-only timeout cannot guarantee billing stops after controller loss. The reviewed Droplet creation API has no documented deletion TTL. A hard deadline needs an independent durable watchdog/control plane holding deletion credentials outside both test guests, with exact IDs/session identity and retries; a guest shutdown timer is only secondary containment. DO API outages can delay deletion even then, so verify destruction and report overruns explicitly. Persist session intent before provisioning, IDs immediately after each successful create, and reconcile by unique session tag after an ambiguous timeout. Partial creation must clean up whichever owned resources exist; never delete all resources in a shared project. Any watchdog hosting choice and associated privilege/billing are unresolved lifecycle decisions, not implemented by this note. [Droplet create/delete API](https://docs.digitalocean.com/products/droplets/reference/api/droplets/), [billing ends on destruction](https://docs.digitalocean.com/products/droplets/details/pricing/).

The operator already chose: infrastructure/invalid-offered-load failure stops the remaining batch; expected capacity failure may continue if the environment remains valid; failed downloads receive bounded recovery followed by deletion at the session deadline. Maximum lifetime is configurable per batch, with recovery inside that same deadline. Exact defaults, access refresh behavior, routing, cleanup watchdog and evidence schema remain with the decision tickets. No CAX11 acceptance box is changed here.
