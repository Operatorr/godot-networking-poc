# Offered-load validity and wire delivery — pending interpretation

The [agreed matrix](https://github.com/Operatorr/godot-networking-poc/issues/30#issuecomment-6145030523) separates collector validity, generator validity, sustainability, delivery quality and legacy harness criteria. Its generator gate is >=99% of scheduled input overall with no persistently starved bot, and it asks for suppressed sends to be counted separately from network drops. The current implementation additionally folds each peer's >=29.7 Hz mapped wire predicate into generator validity. The campaign plan retained that stricter predicate. No classifier or threshold has changed in this proposal.

[Ordinary Idle150 round 2](clean-idle150-r2-20261023.md) passes offered cadence for every peer (29.98213–29.99546 Hz), but 113/150 fail wire cadence on both captures (28.08–29.95333 Hz); 35/36 matrix flags pass. All observed correctness, received-AoI and UDP/socket/capture predicates pass. [Native R5](clean-idle150-audit-r5-20261023.md) independently witnesses specified ENet suppression in a substantial subset, closes packet lifetime, and matches all lifetime Socket handoffs to both captures. That diagnostic does not attribute the ordinary run's full deficit, every retirement, historical cause or application delivery.

Two interpretations are pending the user's answer:

- Retain current strict wire-validity classification. Idle150 remains generator-invalid and cannot advance as a valid server-capacity observation.
- Introduce a **new versioned classification** with offered-load validity separate from wire delivery. Preserve all 36 original flags and their numeric predicates, especially the failed wire flag. Add explicit offered-load validity and wire-delivery outcome fields. The proposed label for this observation would be `valid-offered-load-wire-deficit`, with both `clean_cell_pass=false` and `capacity_pass=false`. Historical classifications stay byte-for-byte unchanged; any later reinterpretation is separate, linked and qualified. This makes no claim that suppression is a code defect or that every missing command has been causally attributed.

The proposal does not grant a clean campaign certificate or close the ticket. Required matched cells, overload characterization, known-defect assessment and historical validity remain outstanding. No transport/input/scheduler/throttle change or threshold relaxation is proposed. Pending an answer, code and classification stay unchanged. Independent required workload cells may proceed under the existing strict gates, without treating Idle150 as a passing rung or claiming a capacity increase.
