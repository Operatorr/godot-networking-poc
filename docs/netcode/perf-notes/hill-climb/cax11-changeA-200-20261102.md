## Scope and reproducibility limits

The stock `report.py` uses 95% of peak population through teardown and assumes colocated
hosts. Its verdict was not used. Temporary `analyze.py` selects the actual full-population
minute from `ticks.csv`, then analyzes each host separately. Linux uses the existing procfs
sampler; Mac uses its existing `ps`/`netstat` fallback plus `ps -M` thread samples.
Bot aggregates include ramp and the 70-second shard runs; the frozen two-thread harness
cannot reconstruct exact-minute RTT quantiles or loss. Bot loss is a mean ENet estimator,
not an end-to-end datagram-loss audit. These limitations do not turn the two observed
failures into a pass. No strict correctness/AoI certification was attempted.

Host samples use their own UTC clocks; SSH clock brackets bound alignment only to roughly
2.3–2.6 s round trips. Server Tick selection is independent of cross-host clocks; Mac
CPU attribution near window edges is approximate. The final exited Mac process can report
zero cumulative CPU, making the helper's whole-run CPU calculation negative; disregard that
field in raw `analysis.json`. The live selected-window CPU and thread samples above are valid.

No previous run is a matched control for this topology. Snapshot cost and UDP overflow
warrant reassessment by the parent task, not automatic Change C implementation. Keep both
200-rung checkboxes unchecked. The task resolution and next decision are recorded on the issue tracker.
